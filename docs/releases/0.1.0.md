# Contextbook 0.1.0 Release Notes

Contextbook v0.1.0 is the MVP launch of a local CLI that helps developers learn the concepts behind the code they just touched.

One-line product promise:

> Learn the concepts behind the code you just touched.

## Who this is for

Contextbook is for developers who already meet concepts in real projects but want better words for them:

- junior/mid frontend developers
- developers using Codex, Claude Code, Cursor-like AI coding sessions, or local CLI workflows
- interview prep users who want to explain why a decision was made, not only what code was written
- project-based learners who prefer examples from their own codebase over generic textbook examples

## Install

```bash
npm install -g contextbook
contextbook setup
contextbook doctor
```

`contextbook setup` installs Codex/OMX and Claude Code helper files by default. It creates helper scripts and guide files, but does not silently overwrite existing hook config. Use `contextbook hooks status` and `contextbook hooks smoke --prompt "cleanup 왜 해야 돼?" --json` to inspect local helper health.

## Main workflow

```bash
contextbook init
contextbook scan
contextbook learn
contextbook why "cleanup 왜 해야 돼?"
```

In supported agent environments after setup:

- Codex/OMX: `$learn`, `$why "cleanup 왜 해야 돼?"`
- Claude Code: `/learn`, `/why "cleanup 왜 해야 돼?"`

## What is included

### Project Memory

Project Memory lives in `.contextbook/` inside the project. It stores deterministic scan output such as package/docs signals, changed files, imports, file/function names, concept evidence, scan provenance, and file index snapshots.

### Learner Memory

Learner Memory lives in `~/.contextbook/learners/default/`. It stores inspectable learner preferences, weak terms, answer history, profile update audit events, and safe learning signals outside the repo.

### Conversation Memory

Conversation Memory is append-only structured event history. It records small learning events such as scan, learn, why, profile, and explicit prompt-signal capture. It does not store raw chat transcripts by default.

### Learning cards

`contextbook learn` recommends 1-3 learning moments from the current project and explains why each was selected.

### Concept answers

`contextbook why "<question>"` answers with project evidence when available and always reports evidence level:

- `direct` — direct project evidence exists
- `related` — nearby/structural evidence exists
- `general` — no project evidence found; answer is general and uncertainty-first

The answer renderer adapts between narrative, plain, structured, interview, and uncertainty-first shapes based on the question, learner memory, and evidence level.

### Agent helpers

`contextbook setup` installs local helper files for Codex/OMX and Claude Code so agents can call the deterministic CLI instead of guessing from chat context.

Hook helpers are safety-bounded:

- no external LLM/API key required
- no raw prompt persistence by default
- low-risk preference automation only through backup/audit/undo
- profile, weak-term, restore, repair, and recovery actions remain explicit

## What is intentionally not included yet

- web dashboard
- cloud sync
- external LLM calls
- fully automatic knowledge tracing
- team-shared learner memory
- broad language/framework coverage beyond deterministic signal rules
- silent profile/weak-term promotion from ambiguous chat

## Verification before publish

The release candidate was checked with:

```bash
npm test
npm run release:smoke
npm pack --dry-run
npm pack --json --dry-run
npm view contextbook
```

`npm view contextbook` returned `E404` before publish, so the package name was not already visible in the public registry from this environment.

`npm publish` is not part of preflight and must be run as a separate explicit release step.
